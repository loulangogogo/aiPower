# Git 自动提交与推送命令

## 功能描述

此命令是一个自动化工作流，旨在简化“修改->提交->推送”的过程。
1. **自动提交**：自动检测当前分支的所有变更，生成符合规范的提交信息，并完成 `git add` 和 `git commit`。
2. **安全推送**：在提交完成后，检查远程状态。若无冲突则直接推送；若有冲突则中止并生成中文报告。

## 工作流程

### 第一阶段：自动提交 (Auto Commit)

1. **变更检测**：
   - 执行 `git status --porcelain` 获取所有变更文件列表。
   - 如果没有检测到任何变更（新增、修改、删除），提示：“当前分支无代码变更，无需提交。”并终止命令。

2. **生成提交信息**：
   - 分析变更类型（feat, fix, refactor 等）。
   - 生成简洁的中文提交标题。例如：“feat: 添加用户登录模块” 或 “fix: 修复首页样式错乱”。
   - *可选*：如果变更较多，可简要列出受影响的文件摘要。

3. **执行提交**：
   - 执行 `git add .` 暂存所有更改。
   - 执行 `git commit -m "<message>"` 完成提交。
   - 显示确认消息：“已提交 [N] 个文件的更改至本地仓库。”

### 第二阶段：安全推送 (Safe Push)

4. **前置检查**：
   - 确认工作区洁净（无未暂存文件）。
   - 确认已配置上游分支 (`branch.<name>.remote` 和 `branch.<name>.merge`)。
     - 若未配置，提示：“当前分支未关联远程，请先执行 `git push -u origin <branch-name>` 建立关联。”并终止。

5. **远程状态同步与冲突检测**：
   - 执行 `git fetch origin` 获取最新远程引用。
   - 比较本地 `HEAD` 与远程 `@{u}`。

6. **决策逻辑**：

   #### 场景 A：无冲突（远程落后于本地）
   - **条件**：远程是本地的祖先（Fast-forward 可行）。
   - **动作**：
     - 执行 `git push`。
     - 显示成功消息：“推送成功！已将包含新提交的分支推送到 [远程分支名]。”

   #### 场景 B：检测到冲突（远程有新提交）
   - **条件**：远程有本地没有的新提交。
   - **动作**：
     - **立即中止**，不执行推送。
     - 生成**中文冲突报告**（见下文示例）。
     - 提供解决方案选项：
       1. `拉取并变基 (Pull & Rebase)`：推荐。将远程更改应用到刚才的提交之上。
       2. `拉取并合并 (Pull & Merge)`：创建合并节点。
       3. `取消操作`：放弃推送，保留本地刚提交的代码。

## 冲突报告示例（中文）

当检测到远程有新提交时，系统将输出如下格式的报告：

```text
⚠️  推送已中止：检测到远程分支有新提交

📊 状态详情：
   - 当前分支：main
   - 远程分支：origin/main
   - 远程领先本地：2 个提交

📝 远程最新提交记录：
   [a1b2c3d] feat(api): 更新用户接口逻辑 (张三) - 2小时前
   [e5f6g7h] fix(db): 修复连接超时问题 (李四) - 5小时前

💡 建议操作：
   您的本地分支（包含刚才的提交）落后于远程仓库。为了防止覆盖同事的最新修改，系统已阻止推送。

   请选择处理方式：
   [1] git pull --rebase origin main （推荐：保持提交历史整洁）
   [2] git merge origin/main       （创建合并节点）
   [3] 取消操作                     （手动处理）
