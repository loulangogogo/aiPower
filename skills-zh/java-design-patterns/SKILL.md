# Java 设计模式

本技能提供 23 种 GoF 设计模式的完整中文参考。每个模式有一篇独立文档，内容依次为：意图、使用说明、使用场景、优点、缺点、完整 Java 示例。

## 先判断，再查文档

设计模式是解决变化点的工具，不是代码装饰。开始查文档前，先确认：

1. 变化点在哪里：对象创建、结构组合，还是对象之间的职责与通信？
2. 哪些部分需要保持稳定，哪些部分需要独立变化？
3. 有没有更简单的做法：直接 `new`、普通接口、组合、函数式接口，或者根本不需要抽象？

确定候选模式后，只读相关文档，不要一次套用多个模式。

## 模式索引

### 创建型

- [01 单例](references/01-singleton.md)：需要严格控制实例数量，例如配置中心、连接池、日志器。
- [02 工厂方法](references/02-factory-method.md)：创建逻辑需要延迟到子类，或要按类型返回不同产品。
- [03 抽象工厂](references/03-abstract-factory.md)：需要创建一族相关产品，并保证它们搭配使用。
- [04 建造者](references/04-builder.md)：构造参数多、可选参数多，需要分步构建不可变对象。
- [05 原型](references/05-prototype.md)：对象创建成本高，或需要复制已有对象并修改少量差异。

### 结构型

- [06 适配器](references/06-adapter.md)：已有接口与客户端期望的接口不兼容。
- [07 桥接](references/07-bridge.md)：两个维度都需要独立扩展，避免 M×N 个子类。
- [08 组合](references/08-composite.md)：需要统一处理树形结构中的叶子节点和容器节点。
- [09 装饰器](references/09-decorator.md)：需要在运行时动态叠加功能，而不是用继承生成大量子类。
- [10 外观](references/10-facade.md)：子系统调用复杂，需要提供一个简单统一的高层入口。
- [11 享元](references/11-flyweight.md)：存在大量重复对象，且大部分状态可以共享。
- [12 代理](references/12-proxy.md)：需要控制访问、延迟加载，或在调用前后增加日志、权限、事务等逻辑。

### 行为型

- [13 责任链](references/13-chain-of-responsibility.md)：多个处理者按顺序尝试处理请求，或需要动态组装处理流程。
- [14 命令](references/14-command.md)：需要把请求封装成对象，支持排队、记录、撤销或宏命令。
- [15 解释器](references/15-interpreter.md)：需要解释简单文法或 DSL，且文法规则相对稳定。
- [16 迭代器](references/16-iterator.md)：需要统一遍历聚合对象，同时隐藏内部结构。
- [17 中介者](references/17-mediator.md)：多个对象形成网状依赖，需要把交互集中到一个中介者。
- [18 备忘录](references/18-memento.md)：需要保存对象快照并恢复，例如撤销、回滚、存档。
- [19 观察者](references/19-observer.md)：一个对象状态变化时需要通知多个依赖方。
- [20 状态](references/20-state.md)：对象行为随内部状态改变，且存在明确的状态转换。
- [21 策略](references/21-strategy.md)：多种算法可以互换，客户端需要在运行时选择。
- [22 模板方法](references/22-template-method.md)：流程骨架固定，只有少数步骤需要子类实现。
- [23 访问者](references/23-visitor.md)：对象结构稳定，但需要不断增加作用于其上的操作。

## 工作流程

1. **识别变化点**：用一句话说明当前代码哪里痛，以及未来最可能变化的是什么。
2. **选 1–2 个候选**：从索引中挑选最贴近的模式，读它的“使用说明”和“使用场景”。
3. **做取舍**：对照“优点/缺点”，说明为什么选它，以及为什么不选更简单的方案。
4. **改写代码**：基于参考示例调整接口、命名和异常处理，保持项目现有风格，不要照搬示例中的业务。
5. **验证**：如环境允许，编译并运行示例；至少检查泛型、空值、并发、资源释放和状态转换边界。
6. **解释**：输出模式名称、解决的问题、引入的代价和替代方案。

## 常见对比

- **工厂方法 vs 抽象工厂**：前者通常创建一个产品，后者创建一族相关产品。
- **适配器 vs 桥接**：适配器是事后转换已有接口；桥接是设计时拆开两个独立变化的维度。
- **装饰器 vs 代理**：装饰器强调叠加功能，代理强调控制访问；两者都实现同一接口并持有目标对象。
- **策略 vs 状态**：策略由客户端选择，算法之间通常不自动转换；状态由内部事件驱动，状态之间会转换。
- **组合 vs 继承**：需要动态组合行为时优先考虑组合；继承适合稳定的“是一个”关系。
- **模板方法 vs 策略**：模板方法用继承固定流程，策略用组合替换整个算法。

## 输出要求

- 用中文解释，代码注释用中文。
- Java 示例优先使用 Java 17+ 语法，保持单文件可编译，不依赖第三方框架。
- 不要为了展示模式而增加抽象；如果直接写法更清楚，明确说明“这里不需要模式”。
- 涉及单例、享元、观察者、代理等模式时，提醒线程安全、内存泄漏、生命周期和性能代价。
- 用户要求对比时，给出适用条件、代价和最小示例，而不是只列定义。
